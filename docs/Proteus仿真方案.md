# Proteus 仿真方案（AutoDoor）

> 目标：在 Proteus 中**分模块验证**，而不是硬啃整个闭环系统。
> Proteus 对电机、传感器的建模是理想化的，试图仿真整机会消耗大量时间却得不到可信结论。

---

## 1. 先说清楚：仿真能验证什么、不能验证什么

这是本文档最重要的一节。仿真与真机的能力边界不同，**把仿真结论当成真机结论是危险的**。

| 项目 | 仿真能否验证 | 说明 |
|---|---|---|
| 门体状态机全部转移 | ✅ **能，且这是主要价值** | 与真机完全同一份 `Door.c` |
| 串口命令协议 | ✅ 能 | Virtual Terminal 直接收发 |
| 软件 PWM 波形与斜坡 | ✅ 能 | 虚拟示波器看 PA4/PA5 |
| 限位逻辑（低电平/高电平判定、双限位冲突） | ✅ 能 | 用拨码开关给电平即可 |
| 按键消抖与长短按 | ✅ 能 | 按键元件 |
| **OLED 显示** | ✅ **能** | 使用 Proteus 的 **OLED12864 I2C**（SSD1306-compatible）模型 |
| **EEPROM 持久化** | ❌ **不能** | 仿真固件使用 **EEPROM stub**，日志走降级路径 |
| **电机真实转速/扭矩** | ❌ 不能 | 模型理想化 |
| **硬件限位断电回路** | ❌ 不能 | 那是模拟电路行为，需真机验证 |
| **中断是否真的触发** | ⚠️ 不确定 | 见下方"EXTI 风险" |

### ⚠️ EXTI 风险与我们的应对

Proteus 的 STM32 模型对 NVIC/EXTI 的支持历来看法不一，部分版本上外部中断不稳定。

**好消息是：本固件不依赖中断边沿也能工作。** `Debounce_Tick1ms()` **每毫秒主动采样引脚电平**，
中断只用来**提前启动稳定窗口**（降低延迟），不参与正确性判断。

这是本轮专门为此加固的：原实现只在中断置位后才检查电平，一旦漏掉边沿，
输入就会永久卡在旧电平。现在即使 **EXTI 完全不触发**，限位、按键、传感器也能正常识别，
只是响应慢 20–25 ms（消抖窗口长度）。

> 这一改动同时在真机上消除了"漏边沿导致输入冻结"的隐患，不只是为了仿真。

## 2. 仿真固件的编译

```powershell
.\tools\build-sim.ps1 -Clean
```

产物：`build-sim/AutoDoorSim.hex` → 在 Proteus 的 STM32 模型属性里设为 **Program File**。

**与真机固件的差异**（仅两处，业务代码完全相同）：

| | 真机 `build/AutoDoor.hex` | 仿真 `build-sim/AutoDoorSim.hex` |
|---|---|---|
| 显示后端 | `Display_Oled.c` + SSD1306 | `Display_Oled.c` + OLED12864 I2C |
| 存储后端 | `EEPROM.c` + AT24C32 | `EEPROM_Stub.c`（报告器件缺失） |
| Flash 占用 | 22692 B (34.6%) | 19020 B (29.0%) |

两者共用 `tools/sources.ps1` 的源文件清单，不可能各自漂移。

## 3. 仿真原理图接线

### 3.1 MCU 与基础

| 项 | 接法 |
|---|---|
| U1 | STM32F103C8（Proteus 库中搜 `STM32F103C8`） |
| 晶振 | 8 MHz + 22 pF ×2 接 OSC_IN/OSC_OUT（或用模型内部时钟，见 §5 注意） |
| 复位 | NRST 经 10 kΩ 上拉，接一个按键到 GND |
| BOOT0 | 经 10 kΩ 下拉到 GND |
| 电源 | VDD/VDDA 接 +3.3V，VSS/VSSA 接 GND，每个 VDD 配 100 nF |

### 3.2 OLED12864 I2C 显示

| OLED12864 引脚 | 接 MCU |
|---|---|
| SCL | **PB10** |
| SDA | **PB11** |
| VCC | **+3.3 V** |
| GND | **GND** |

**还要加两个上拉电阻**：`PB10` 和 `PB11` 各经一个 **4.7 kΩ（或 10 kΩ）到 +3.3 V**。

> ⚠️ **这一步漏掉的话，开机第一行就会是 `I2C idle : NO (bus held low)`，`Display : not found`。**
>
> I2C 是开漏总线，**没有上拉就没有高电平**。固件的 `MyI2C_IsIdle()` 一上电就检查两条线
> 是否都被释放到高；靠 10 kΩ 上拉（见 §3.3）读不到"H"时，它会如实报告总线被拉死 ——
> 那是**正确的诊断**，不是 bug。真机上 OLED 模块通常自带这两个电阻，所以这一点只在
> 仿真里容易漏。

> 仿真使用 OLED12864 的 I2C 接口，因此 PB10/PB11 与真机保持一致；
> EEPROM 仍由 `EEPROM_Stub.c` 替代，仿真**不会**验证持久化（见 §4.1）。

### 3.3 输入（按键 / 拨码开关）

| 网络 | 引脚 | 元件 | 说明 |
|---|---|---|---|
| 开门限位 | **PA0** | 拨码开关或按键到 GND + 10 kΩ 上拉 | **按下 = 低电平 = 已到位** |
| 关门限位 | **PA1** | 同上 | |
| 门外（进门） | **PB12** | 按键到 GND + 10 kΩ 上拉 | 按下 = 低电平 = 检测到人 |
| 门内（出门） | **PB13** | 同上 | |
| KEY1 启停 | **PB5** | 按键到 GND + 10 kΩ 上拉 | |
| KEY2 模式 | **PB6** | 同上 | |
| KEY3 手动开门 | **PB7** | 同上 | |
| KEY4 手动关门/急停 | **PB8** | 同上 | 长按 = 急停 |

> **限位开关的电平语义**：当前固件读回使用 NO 触点，门离开限位时触点断开、内部上拉读高，
> 到限位时触点闭合接地、读低。仿真按键应一端接 **GND**，另一端接 **PA0/PA1**，
> 使用 10 kΩ 上拉，按下即表示到位。

### 3.4 电机驱动（可选）

| 项 | 接法 |
|---|---|
| 驱动 | `L293D` 或 `L298` 模型（Proteus 对 L9110S 支持不稳） |
| 输入 | IN1 ← **PA4**（IA），IN2 ← **PA5**（IB） |
| 输出 | OUT1/OUT2 → `MOTOR` 元件 |
| 使能 | EN 接 +5V（对应 L9110S 无使能脚） |

> 仿真里电机模型不会真实转动，**主要看输入端的 PWM 波形**（见 §4.3）。

### 3.5 蜂鸣器与 LED

| 网络 | 引脚 | 元件 |
|---|---|---|
| 蜂鸣器 | **PB3** | `BUZZER`（有源）或 `SOUNDER` |
| 状态 LED | **PB4** | LED + 330 Ω 到 GND |

### 3.6 串口

| 项 | 接法 |
|---|---|
| USART1 | PA9(TX) → `COMPIM`/`VIRTUAL TERMINAL` 的 RXD；PA10(RX) ← TXD |
| 参数 | **115200 8N1** |

## 4. 五个分模块测试

按顺序做，每步都有**明确的判定标准**。

### 4.1 测试一：启动与自检

**运行仿真**，Virtual Terminal 应输出：

```
========================================
 AutoDoor  STM32F103C8T6  v1.0
========================================
I2C idle      : yes                    ← 预期：OLED12864 I2C 总线空闲
Display       : OK                     ← 预期：OLED12864 应答
EEPROM @0xA0  : FAILED at 0x0000       ← 预期：stub 报告器件缺失
Log           : UNAVAILABLE - running with defaults
Limits        : open=0 closed=1
Door          : IDLE (press KEY1 to enable)
```

**判定**：
- ✅ `Log: UNAVAILABLE` 出现 → **降级路径正确**（这是仿真特意验证的行为）
- ✅ `Door: IDLE` → 上电时读到关门限位闭合，位置判断正确
- OLED12864 第一行显示 `AutoDoor`，其余区域显示状态和事件

> 仿真**不能**验证 `EEPROM: OK` 与 `records=N` 持久化，那需要真机。

> **一个副作用要提前说明**（round 10 起）：没有 EEPROM 时 `LOG?` / `LOG?ALL` / `LOG?<n>`
> 会回 `ERR EEPROM (log not fully persisted)`，而不是以前那句 `OK LOG EMPTY`。
> 这是**故意的**：日志不可用时回"空"是在撒谎 —— 它根本无从知道有没有记录。
> （`LOG?CLEAR` 本来就回 `ERR EEPROM`，没有变化。）
> 仿真里请把这些 `ERR EEPROM` 当作**预期输出**，它和 `Log: UNAVAILABLE`
> 一起证明降级路径是自洽的。

### 4.2 测试二：按键与模式

| 操作 | 预期 |
|---|---|
| 按 KEY1 | 串口出现 `SYSTEM_START`，状态从 `STOPPED`/`IDLE` 变化；OLED 状态变化 |
| 按 KEY2 | `MODE_CHANGE`，模式在 AUTO/MANUAL 间切换 |
| 按 KEY1 再按 | `SYSTEM_STOP` |

**判定**：每次按键**只产生一条**事件。若一次按下出现多条 → 消抖窗口过短。

### 4.3 测试三：PWM 波形（虚拟示波器）

1. 给 PA4 与 PA5 各接一个 **OSCILLOSCOPE** 通道
2. 按 KEY1 使能，按 **KEY3**（手动开门）
3. 观察波形

**预期**：
- **载波周期约 10 ms（100 Hz）**
- **占空比在约 400 ms 内从 0% 线性升到 70%** —— 这就是软启动斜坡
- 换向（KEY3 → KEY4）时，**两者会先同时为低约 20 ms** —— 这是换向死区

**判定**：
- ❌ 占空比瞬间跳变 → 斜坡没生效
- ❌ 换向时两路直接翻转 → 死区没生效，真机上会烧 H 桥

> 这是仿真**最有价值**的一项：死区和斜坡在真机上很难观察，示波器上一目了然。

### 4.4 测试四：门体状态机全流程

用拨码开关模拟限位，用按键模拟传感器。

| 步骤 | 操作 | 预期串口 |
|---|---|---|
| 1 | KEY1 使能 | `SYSTEM_START` |
| 2 | 按"门外"键 | `ENTER_IN` → `OPEN_START` → OLED 显示 `OPENING` |
| 3 | 拨动**开门限位**开关 | `LIMIT open edge` → `OPEN_DONE DUR=xxxxms` → `OPEN` |
| 4 | 等待 5 s 不操作 | `CLOSE_START` → `CLOSING`，蜂鸣器响 |
| 5 | 拨动**关门限位**开关 | `CLOSE_DONE` → `IDLE` |
| 6 | 重复 2，然后立刻再按一次"门外" | 倒计时**重新开始**（门保持开启） |
| 7 | 关门途中按"门内"键 | `REVERSE` → 门立即反转到 `OPEN` |

> 第 7 步是**最重要的安全行为**：关门途中检出人员必须反转。

### 4.5 测试五：故障与急停

| 注入 | 预期 |
|---|---|
| 让门开着（步骤 3 后）**不拨限位**，等 5 s | `FAULT_OPEN_TIMEOUT` → `STOPPED`，蜂鸣器三短鸣，LED 双闪 |
| 长按 KEY4 | 立即停机 + `ESTOP`，长鸣 |
| 急停后再发 `DOOR=OPEN` | **不动作**（故障锁存） |
| 用串口发 `RESET` | 故障清除，可以重新使能 |
| 同时在串口发 `STATUS?` | 显示 `FAULT=ESTOP` |

## 5. 常见问题

| 现象 | 原因与处理 |
|---|---|
| OLED 只显示空白 | 检查 OLED12864 的 VCC/GND、PB10/PB11、地址和 I2C 上拉 |
| OLED 无显示 | 确认使用 SSD1306-compatible OLED12864 I2C 模型，地址为 `0x78` |
| 门外/门内按键无反应 | 确认接的是 **PB12/PB13**（不是 PB0/PB1——那是旧引脚） |
| 串口无输出 | 检查 PA9→RXD 是否**交叉**，波特率是否 115200 |
| 按键无反应 | 若 EXTI 在你的 Proteus 版本上不触发，**等 20–25 ms** —— 固件靠 1 ms 采样兜底，应当仍能识别 |
| 限位拨动无反应 | 确认上拉/下拉方向：**"按下 = 低"** 才是"到限位"（见 §3.3）。写成"按下 = 高"就永远不会识别 |
| 电机不转 | 仿真里正常，看 PWM 波形即可 |
| 时钟不对导致延时错乱 | 在 STM32 模型属性中确认 **Crystal Frequency = 8 MHz** |

## 7. 必须转到真机验证的项目

仿真通过**不等于**系统可用。以下项目只能在真机验证，见 `docs/上电调试步骤.md`：

1. **EEPROM 持久化**（断电重启后记录与配置是否保持）
2. **硬件限位断电回路**（拔掉限位线电机是否立即停 —— fail-safe）
3. **I2C 总线在电机噪声下的健壮性**（`BusRecover()` 是否会真的被触发）
4. **电机实际转速、扭矩、软启动手感**
5. **蜂鸣器与 LED 的实际可辨识度**
6. **OLED 显示**（仿真中从未跑过 OLED 后端）
