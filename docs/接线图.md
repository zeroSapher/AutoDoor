## 0. 先选你要接到哪一步

| 目标 | 需要接的 | 备注 |
|---|---|---|
| **A. 只确认能烧、能连** | **什么都不接**，只插 ST-Link | `docs/上电调试步骤.md` 步骤 0 |
| **B. 跑状态机/串口/日志/OLED** | + USB-TTL、OLED、EEPROM、4 个按键、2 个传感器按键、蜂鸣器、LED | **不接限位和舵机**；门的位置由行程时间推算，这就是**默认（出厂）构建**，没有任何构建开关 |
| **C. 完整（含舵机）** | + **舵机自己的 5 V 电源（≥ 1 A）**、470–1000 µF 电解、SG90 舵机 | **限位开关不装**：PA0/PA1 空着不接。第 5 节是"当年接限位"的作废记录 |

> B 阶段就足以验证 90% 的固件逻辑（状态机全流程、全部串口指令、日志持久化、
> OLED 三屏）。**建议先走完 B 再接舵机**，否则一旦有问题你分不清是代码还是接线。
> 舵机接错电源的代价比电机更隐蔽：现象是"门动一下、板子跟着重启"，看起来像固件 bug。

> **本设计不安装限位开关**（`Core/main.h` 的 `AUTODOOR_NO_LIMITS` 默认为 1）。
> 门的到位由**标定行程时间** `DOOR_TRAVEL_MS`（默认 **1500 ms**；`TRAVEL=<ms>` 可
> 现场改到 600..4000 并持久化）推算，
> 行程看门狗则为 `DOOR_TRAVEL_MS + DOOR_TRAVEL_MARGIN_MS` = **2700 ms**（默认值）。
> 代价见 `Core/main.h` 开头那段"WHAT IS GIVEN UP" —— 没有软件快速停机层、
> 查不出限位线故障、也没有绝对位置与修正。若以后真的要装回限位，
> 用 `.\tools\build.ps1 -WithLimits` 构建可选变体（读 PA0/PA1，看门狗回到 5000 ms）。

## 0.1 最小验证接线：只看 OLED 和串口

**目标**：确认「能烧录 + OLED 能显示 + 串口能收发」。需要 4 样东西，
**一共 12 根线**，不需要 5 V、不需要舵机、不需要限位。

### 接线

**① ST-Link（4 根）**

| ST-Link | Blue Pill 丝印 |
|---|---|
| `3.3V` | **3V3** ← 本步用它给板子供电 |
| `GND` | **GND** |
| `SWDIO` | **PA13**（有的板子只印 `A13`/`DIO`） |
| `SWCLK` | **PA14**（印 `A14`/`CLK`） |

**② USB-TTL / CH340（3 根，`VCC` 不要接）**

| USB-TTL | Blue Pill 丝印 |
|---|---|
| `TXD` | **PA10**（`A10`） |
| `RXD` | **PA9**（`A9`） |
| `GND` | **GND** |

**③ OLED 0.96" I2C（5 根 + 2 个电阻）**

| OLED | 接到 |
|---|---|
| `VCC` | **3V3** |
| `GND` | **GND** |
| `SCL` | **PB10**（`B10`） |
| `SDA` | **PB11**（`B11`） |
| 4.7 kΩ 电阻 ×2 | `PB10`→`3V3`、`PB11`→`3V3` |

### ⚠️ 三个坑，按顺序排

1. **上拉电阻必须有。** I2C 是开漏：**没有上拉就没有高电平**。先翻 OLED 模块背面
   有没有印 `472`（4.7 kΩ）的电阻 —— 很多模块自带；**不确定就外加两个**，
   并联成 2.35 kΩ 也完全没问题。
2. **OLED 接 3V3，不要接 5V。** 模块自己的上拉是跟着 `VCC` 走的，接 5 V 就把
   5 V 拉到 `PB10`/`PB11` 上。F103 这两脚虽然 5 V 容忍，但以后 EEPROM 挂同一条
   总线上就会一团乱。**整条总线统一 3V3。**
3. **只用一个电源。** USB-TTL 的 `VCC` 不接，板子由 ST-Link 的 3.3 V 供电
   （这一步没有舵机，电流很小）。接了 `VCC` 就变成两个电源并联。

### 烧固件（默认构建；不需要限位开关）

```powershell
.\tools\build.ps1 -Clean -Flash
```

> 默认构建就是**不装限位**的出货配置：`Limit.c` 不碰 PA0/PA1、不占 EXTI，
> 位置按**命令方向 + 已走时间**推进（0 % = 全关，100 % = 全开，全程
> `DOOR_TRAVEL_MS` = 1500 ms，可 `TRAVEL=<ms>` 现场改）。上电时推算位置为 0，所以 `open=0 closed=1`、
> 门直接是 `IDLE`。想装限位才加 `-WithLimits`（详见 §2.2 与第 5 节）。

### 预期串口输出（115200 8N1，逐行对照）

```
========================================
 AutoDoor  STM32F103C8T6  v1.0
========================================
I2C idle      : yes
Display       : OK
EEPROM @0xA0  : FAILED at 0x0000
Log           : UNAVAILABLE - running with defaults
*** NO LIMIT SWITCHES: position is a timed estimate (1500ms) ***
*** the travel watchdog (2700ms) is the only overrun protection ***

Position      : timed estimate, 1500ms travel (open=0 closed=1)
    state: INIT -> IDLE
Door          : IDLE (press KEY1 to enable)

AutoDoor ready. boot#0  records=0  delay=5000ms
type HELP for commands
```

> **顺序要按上面这份对**：`I2C idle` / `Display` / `EEPROM` / `Log` 四行在最前，
> 两条 `***` 警告与 `Position` 在**读完 EEPROM 之后**才打（它们打印的是**当前生效**的
> 行程时间，默认 1500 ms，看门狗 = 它 + 1200）；缩进的 `    state: INIT -> IDLE`
> 由状态回调插在 `Position` 与 `Door` 之间，会被误看成"串口把两行接在了一起"，
> 其实那是**两行**。这里没接 EEPROM，`Log_Init()` 在读配置之前就返回，所以 `boot#` 一直是 **0**（不会递增）。

### 判定 —— 这两行就是结论

| 串口行 | 含义 | 通过条件 |
|---|---|---|
| `I2C idle : ...` | 两条 I2C 线释放后是否为高 → **证明上拉电阻在** | **必须是 `yes`** |
| `Display : ...` | `MyI2C_Probe(0x78)` 是否被应答 → **证明整条链路通** | **必须是 `OK`** |

**`EEPROM FAILED` 与 `Log UNAVAILABLE` 是预期的** —— 这一步没接 EEPROM，
固件如实报告并走降级路径。**它们不算失败。**

OLED 上此刻应显示状态屏（门态 / 模式 / 延时）。

### 不通过时怎么查

| 现象 | 原因 |
|---|---|
| `I2C idle : NO (bus held low)` | **上拉电阻没接**；或 SDA/SCL 接反；或器件短路 |
| `I2C idle : yes` 但 `Display : not found` | 总线是好的，OLED 不应答 → `VCC` 没接/接错、地址不是 0x78、`SCL`/`SDA` 互换 |
| 串口**完全没输出** | `PA9`/`PA10` **没交叉**（TX→RX、RX→TX）；波特率不是 115200；USB-TTL 的 GND 没接 |
| 串口有乱码 | 波特率不对；或板子主频不对（本固件直接用内部 **8 MHz HSI**，不用外部晶振，也不启用 PLL） |
| 串口有输出但 `boot#` 每次都是 1 | 正常 —— 没接 EEPROM，`bootId` 无法持久化 |

### 想顺手把状态机也走一遍（可选，只需一根线）

`PB5` 接一个按键到 `GND`（KEY1），然后：

| 操作 | 预期 |
|---|---|
| 按一下 KEY1 | `SYSTEM_START`，`Door: IDLE` |
| 串口发 `DOOR=OPEN` | `OK DOOR OPENING` → **约 1.5 s 后自己到位**：`LIMIT open edge` + `OPEN_DONE` → `OPEN` |
| 等 5 s 不动 | 自动 `CLOSE_START` → **再约 1.5 s** → `CLOSE_DONE` → `IDLE` |

> **没有限位开关可以按。** 位置是按行程时间（`DOOR_TRAVEL_MS` 默认 1.5 s，`TRAVEL=<ms>` 可改）推算的：
> 舵机一开始朝那一端走，推算位置就朝那一端推进；走满这一段行程时间，`Limit.c` 自己判定"到位"，
> 于是状态机在没有任何外部输入的情况下转成 `OPEN`（开门）或 `IDLE`（关门）。
> 串口那行 `LIMIT open edge` 仍然会打印 —— 它不是开关触发的边沿，
> 而是**推算到位时固件自己产生的那条边沿**（`Limit.c` 里 `s_simOpenEvent`）。
>
> 这一步验证的是**状态机、串口协议、日志、显示**这条链，
> **不是**舵机（这一步没接舵机），也没有限位这条链可验。
> 没接 KEY1 时 `DOOR=OPEN` 会回 `ERR BUSY (state=IDLE run=0)` —— 系统未使能，正常。

> 舵机在旁边动作的时候，这个建议值得听。**限位已取消，所以这一条只适用于按键与传感器。**

## 2. 各模块怎么接

### 2.1 SG90 舵机（TIM3_CH1 硬件 PWM，**PA6**）

本分支的执行器是 **SG90 舵机**，不是 130 直流电机，所以这一节整段重写。
舵机只有 **3 根线**，而且**不能从板子上取电**：

| SG90 线色 | 接到 | 说明 |
|---|---|---|
| 棕 / 黑（GND） | **舵机电源负极**，并与 **板 GND** 相连 | **必须共地**。舵机电源地不连板地时，PA6 的脉冲在舵机看来没有参考电平 → **舵机一动不动**，这是"舵机没反应"最常见的原因 |
| 红（+5 V） | **舵机自己的 5 V 电源，≥ 1 A** | **不要**接板的 3V3，也**不要**用 ST-Link 的 5 V 引脚 |
| 橙 / 黄（信号） | **PA6**（`TIM3_CH1`，AF 推挽输出） | **3.3 V 逻辑**，50 Hz 帧；1000 µs = 关、2000 µs = 开 |

**电源**：舵机电源正负极之间**就近**并一个 **470–1000 µF 电解电容**（正极对 5 V、
负极对 GND），电容装在**舵机那一端**而不是板子那一端。堵转的 SG90 会拉到几百 mA，
没有这个电容，舵机自己的 5 V 会被拖出一个台阶。

**PA6 上是固定的 50 Hz 帧**（周期 20 ms），脉宽就是角度：`SERVO_CLOSED_US` = **1000 µs**、
`SERVO_OPEN_US` = **2000 µs**（`Core/main.h`）。SG90 的机械量程约 500..2500 µs，
所以这 1000 µs 的差正好是 **90°** 的行程（1000 µs 在量程的低端，不是机械端点）。

| 状态 | PA6 上的脉宽 | 说明 |
|---|---|---|
| 上电 / 复位 | 1000 µs（关位） | `Motor_Init()` 把"当前脉冲"与目标都置到关位 |
| 开门中 | 1000 → 2000 µs，按行程时间逐毫秒推进 | 舵机跟着脉冲扫过去 |
| 关门中 | 2000 → 1000 µs | 同上 |
| 到位 / `STOP` / 急停 | **当前**脉宽，保持不变 | 舵机**保持**在这个角度；没有滑行、也没有断电 |

**没有可调的占空比。** 舵机是**位置执行器**：50 Hz 脉冲串编码一个角度，它去那个角度
并**保持**。没有占空比、没有滑行（coast）、没有方向对、也没有换向死时间 —— 门的快慢
完全由**行程时间**决定：它决定固件每毫秒把脉冲往目标挪多少。

| 参数 | 值 | 说明 |
|---|---|---|
| `DOOR_TRAVEL_MS` | 默认 **1500** ms | 走完 1000 µs 这一段（关→开）所用的时间 |
| `TRAVEL=<ms>` | **600..4000**，写 EEPROM | 现场改行程时间，**运行中即时生效**；本台架 EEPROM 不应答时会多一句 `(NOT PERSISTED - eeprom write failed)`，数值当次**仍然生效** |
| 每 20 ms 帧的位移 | 1500 ms → **13 µs/帧** | 0.67 µs/ms × 20 ms。SG90 的死区约 10–20 µs/帧，13 µs 刚好越过去，所以门是**扫**过去而不是一格格跳；4000 ms 只剩约 5 µs/帧，会开始抖 |

> 所以本分支"调速"叫 **`TRAVEL=`**，不叫 `SPEED=`：`SPEED=50` 会回
> `ERR N/A - SG90 speed is fixed (use TRAVEL=<ms>)`。本分支**没有** `MOTOR_DEFAULT_DUTY`、
> 也**没有** `MOTOR_DEADTIME_MS` 在起作用 —— `main.h` 里留下来的那两个直流电机宏
> 被 `Motor_SetDuty()` 直接忽略（函数体就是 `(void)percent`）。

**时钟**：`main.h` 里**故意没有** TIM3 的时钟常数。固件在 `Motor_Init()` 里读**实际的
APB1 定时器时钟**再算预分频，保证 1 µs 计数：本板 **8 MHz → `PSC=7`**（只有 72 MHz
才轮到 71）。这颗 8 MHz 晶振**从来没起振过**（用 SWD 强行打开 HSEON，`HSERDY` 始终
不置位），所以 MCU 跑**内部 8 MHz HSI**，50 Hz 帧与 1 ms 系统节拍仍然精确。
**不要把 72 MHz 系统时钟写成事实** —— 这个坑本分支真踩过：写死 72 MHz 时帧变成
5.5 Hz、脉宽 9 ms，舵机直接忽略信号不动，而 UART 与延时全都正常，只有舵机不动。

### 2.2 限位开关（**已取消：现在不装**）

**本设计不再安装限位开关。** 门的位置由**标定行程时间**推算：
舵机一开始朝那一端走，`Limit.c` 的推算位置就朝那一端推进，走满 `DOOR_TRAVEL_MS`（默认 1500 ms，`TRAVEL=<ms>` 可现场改）
即判定"到位"。**PA0/PA1 悬空，不要往这两脚接任何东西**（见 §1.2）。

**如果以后真的要装回限位**，需要两件事：

1. **硬件**：2 个 KW12-3（或光电/霍尔开关）、每个输入 1 个 10 kΩ 上拉到 +3V3、
   1 个 100 nF 到地（硬件消抖）。这些**不在当前 BOM 里**（见 §6）。
2. **固件**：用 `.\tools\build.ps1 -WithLimits` 构建（即 `-DAUTODOOR_NO_LIMITS=0`）。
   只有这个可选变体才读 PA0/PA1、占 EXTI0/EXTI1，行程看门狗也回到固定的 5000 ms。

> 默认构建（`AUTODOOR_NO_LIMITS=1`）**完全不碰**这两个引脚，所以光接硬件、
> 不换构建，限位不会有任何作用 —— 而你会以为它在工作。

以下是**当年接限位时的做法**，保留下来，供以后真加回限位时参考
（这套接法对应 `-WithLimits` 变体；`Limit.c` 的 `activeLevel = 0U` 就是照它写的）：

| KW12-3 触点 | 接到 |
|---|---|
| `COM` | **GND** |
| `NO` | **PA0**（开门限位）/ **PA1**（关门限位） |
| `NC` | **空着**（原因见第 5 节，那一整节现在也作废了） |

加 10 kΩ 上拉到 3V3、100 nF 到 GND（可选但推荐）。

**先用万用表找出三个脚**（不同批次脚位不一样）：

1. 手柄**不按**时，哪两个脚导通 → 那就是 `COM`–`NC`
2. 剩下那个是 `NO`
3. 按下手柄，确认 `COM`–`NC` **断开**、`COM`–`NO` **导通**

> 极性：**到位时引脚读低**（NO 闭合接地）。这已经写进 `Limit.c`（`activeLevel = 0`）。
> 若你量出来相反，**改接线或改 `activeLevel`，不要两个都不改** ——
> 那样限位会完全不起作用，而你会以为它在工作。

### 2.3 按键（KEY1–KEY4）

一端接 MCU 引脚，另一端接 **GND**。内部上拉已开。

| 按键 | 引脚 | 短按 | 长按（按住 > 1.5 s）|
|---|---|---|---|
| KEY1 | PB5 | 启停系统（`RUN`）| 同短按 |
| KEY2 | PB6 | 切 AUTO / MANUAL | 切 OLED 屏幕 |
| KEY3 | PB7 | 手动开门 | 退出日志屏，回状态屏 |
| KEY4 | PB8 | 手动关门 | **急停**（抬起）|

`KEY_DEBOUNCE_MS = 20`、`KEY_LONGPRESS_MS = 1500`：点触短于 20 ms 会被消抖忽略；
按住超过 1.5 s **只算长按，不会再补一个短按**（`Key.c` 用 `consumed` 标志保证）。

> **KEY3/KEY4 与屏幕导航共用按键**，规则是"导航绝不抢门指令"：
>
> - **短按**：只有在 **手动模式 + 系统未使能（`RUN=0`）+ 日志屏已打开** 三者同时成立时
>   才变成翻页（KEY3 翻旧、KEY4 翻新）；其余情况一律当成开门 / 关门。
> - **长按**：不是门指令，所以**任何模式、任何使能状态**下都能**从任意非状态屏返回状态屏**
>   —— 事件屏和日志屏都行。
>
> **屏幕有三个**，KEY2 长按循环切换：
>
> | 屏 | 标题 | 内容 |
> |---|---|---|
> | 状态屏 | （无标题，两行大字）| 门态 / 模式 / 故障 / 记录数 |
> | **事件屏** | `Recent events` | 实时事件 |
> | 日志屏 | `Log n/m` | 掉电保存的历史；**没接 EEPROM 时只有 `(no records)`** |
>
> 修复史：长按最初与短按共用同一道门槛，在 AUTO 模式（默认）或 `RUN=1` 时是**静默空操作**；
> 第一次修好后仍**只认日志屏**，于是在**事件屏**上长按依然毫无反应 —— 而那恰恰是没接 EEPROM 时
> 唯一有内容、看起来最像"日志界面"的一屏。两处都已修，`tools/bench-chain.ps1` 的 F 段专门盯这条。
> 详见 `docs/设计文档.md` §12.14。

### 2.4 门内外传感器（现在用按键模拟）

| 传感器 | 引脚 | 说明 |
|---|---|---|
| 门外（进门） | **PB12** | 一端接引脚，一端接 GND。按下 = 检测到人 |
| 门内（出门） | **PB13** | 同上 |

> **不是 PB0/PB1** —— 那是旧引脚，在 round 11 改掉了。
> 原因：STM32F1 的 EXTI 线按**引脚编号**共用，PB0/PB1 会和限位抢 EXTI0/EXTI1，
> 结果是**限位一个中断都没有**。现在 `main.h` 有编译期断言挡住这种重复。
>
> 限位取消之后 EXTI0/EXTI1 是空的，但这条历史仍然成立：**若以后用 `-WithLimits`
> 装回限位，那两个编号立刻又被占用**，所以传感器留在 PB12/PB13 才是稳的。

### 2.7 蜂鸣器（有源）

| 接法 | 说明 |
|---|---|
| **模块自带驱动** | 信号脚 → **PB3**，VCC/GND 接 3V3/GND（3.3 V 型）或 5 V（看模块） |

| 状态 | 模式 |

| OPENING | 常亮 |
| OPEN | 慢闪（正在倒计时） |

## 3. 电源与地

### 3.1 两个电源域：板子一路，舵机另一路

```
                     ┌──────────────────────┐
 USB / ST-Link ──────┤ 5V                   │  ← 只给板子，不带舵机
 (或 5 V 适配器)     │        Blue Pill     │
                     │  (STM32F103C8T6)     │
                     │   AMS1117 ──▶ 3V3    │
                     └───┬──────────┬───────┘
                         │          │
                   3V3 ──┴──▶ OLED / EEPROM / 上拉电阻 / 传感器按键
                         │
                   GND ──┴──────────────┬────────────────┐
                                        │           （板子的地）
   舵机 5 V 电源(≥1 A) ─┬─▶ 470~1000 µF 电解 ──▶ SG90 红线
   （独立，只带舵机）    └─▶ SG90 棕/黑线 ─┐        SG90 橙/黄 ──▶ PA6
                                          │
   两个电源的负极 ──── 单点汇聚（唯一共地点）◀┘
```

| 域 | 供给 | 谁用 |
|---|---|---|
| **3.3 V** | Blue Pill 板上 AMS1117 | OLED、EEPROM、I2C 上拉、传感器/按键（其实用内部上拉也行） |
| **5 V（舵机专用）** | **独立 5 V 电源，≥ 1 A** | **只给 SG90**，舵机处就近并 470–1000 µF |
| **5 V（板上）** | USB 或 ST-Link 的 5 V 脚 | 只给板子；**不要拿它带舵机** |
| **VBAT** | 不用 | — |

### 3.2 ⚠️ 三条供电纪律

1. **舵机必须有自己的 5 V（≥ 1 A），而且必须共地。** 不要用板的 3V3、也不要用
   ST-Link 的 5 V 脚带舵机：小 dongle 的 5 V 直通 USB，堵转的 SG90 拉几百 mA，
   会把板子一起拉跌 —— 现象是"门动到一半板子复位"，很容易被当成固件 bug。
   **信号是 3.3 V 逻辑、舵机电源是 5 V，两者只在"地"这一点上发生关系。**
2. **舵机电源的地必须接到板子的地。** 只接 5 V 不接地时，PA6 的脉冲在舵机看来
   没有参考电平 → **舵机一动不动**。这是本项目"舵机完全没反应"的第一大原因。
3. **地单点汇聚，舵机电流不要流经 MCU 地线。** 正确做法：舵机电源负极 → 一条粗线到
   舵机，**另一条**到 Blue Pill 的 GND，两条只在舵机电源负极处汇合。
   若让舵机电流穿过 MCU 的地线，I2C 会出错、ADC 会飘、还可能复位。

## 5. ⚠️ 限位"硬件断电"层的死锁问题（**已作废**，仅供以后想加回限位时参考）

> **本节已作废。** 限位开关不再安装（见 §2.2），所以"NC 触点串进 `+5V → VM`"
> 这条硬件断电回路根本不存在，下面这个死锁问题也随之不存在 —— 它当初成立的前提
> 是"门静止时压住限位开关"，而那个前提只属于装了限位的那套硬件。
> 保留本节只有一个用途：**以后真要加回限位时，先在这里选定方案再动手**。

### 5.1 旧文档写的接法

`docs/立创EDA原理图设计说明.md` 与 `docs/上电调试步骤.md` 都写着：

```
+5V ──[ 开门限位 COM-NC ]──[ 关门限位 COM-NC ]──▶ VM(L9110S)
```

意图是：限位一到位就用**机械触点切断电机供电**，即使 MCU 死机也停得住
（fail-safe，失效方向导向"断开"）。这个意图是对的。

### 5.2 但它和软件模型**互斥**

门在**静止关闭**时，关门限位是被门体**压住**的 → 它的 `NC` 是**断开**的
→ 两个 NC 串联 → `VM` 没有电 → **电机根本转不起来** → **门永远开不了。**

而且软件**要求**这个开关在静止时被压住：装了限位时，`Door_Init()` 靠
`Limit_IsClosed()` 判断"门是关着的"并进入 `IDLE`。如果门静止时开关没被压住，
固件会认为门位置未知。

> **两个各自都对的子系统，不能同时成立** —— 这正是本项目反复出现的那类问题，
> 只不过这次在硬件层。而且它和 round 12 修掉的软件 bug 是**同一个形状**：
> **保护动作发生在"门需要动"的状态里**（那个是释放边沿切电机，这个是停位切断供电）。

### 5.3 一分钟确认（万用表，不用通电）

门放在静止关闭位置，量**关门限位**的 `COM`–`NC`：

- **断开** → 死锁成立，**不要**按旧文档串这个回路
- 导通 → 说明你的开关是"碰一下就离开"的安装方式；但那样固件又会认为门没关到位
  （`Limit_IsClosed()` 为假），得回到 §5.4 重新选一条路

### 5.4 两条出路

**方案 A（推荐先做）：限位只做信号，硬件断电层**暂时留空**。**

- 限位接 `NO` → PA0/PA1（§2.2），`NC` 空着；固件必须用 `-WithLimits` 构建
- 停机由**软件**做：限位 EXTI 立即 `Motor_EmergencyStop()`（round 11/12 已修好）
- 代价要说清：**MCU 死机时软件层失效**，电机会一直顶到机械限位处堵转，
  L9110S 与电机会发热。桌面模型 + 短行程 + 演示场合可以接受，
  **但文档里不能再声称"硬件断电层存在"**
- 这也是**现在的默认构建（不装限位）所放弃的东西**：连这一层软件快速停机都不存在，
  唯一的超程保护是行程看门狗（`DOOR_TRAVEL_TIMEOUT_MS` = 默认 2700 ms，即当前行程时间 + 1200）

**方案 B（要真正的硬件层就得这样）：做"超行程"切断，而不是"停位"切断。**

- 每个方向装**两个**开关（或用一个由门体继续推动的杠杆）：
  - 第一个开关在 **90°（电气限位）** 动作 → 只做**信号**给 MCU
  - 第二个开关在 **约 95°（机械超行程）** 才断开 → 串在 `+5V → VM` 里
- 静止在 90° 时第二个开关**仍闭合** → 无死锁；只有"软件没停住、继续冲到 95°"
  才会被硬件切断 → **真正的 fail-safe，且不挡正常动作**
- 代价：再买 2 个 KW12-3，并要把杠杆几何调到 90°/95° 两个动作点

> **一句话**：串联 NC 断电只能切"**过头**"，不能切"**到位**"。
> 旧文档把它当成了后者。

## 8. 常见错误对照

| 现象 | 首先怀疑 |
|---|---|
| 串口无输出 | PA9/PA10 **没交叉**；波特率不是 115200 |
| `I2C idle: NO (bus held low)` | **上拉电阻没接**；或 SDA/SCL 接反；或器件短路 |
| `Display: not found` | OLED 的 VCC/GND、地址 0x78、PB10/PB11 |
| `Log: UNAVAILABLE` | EEPROM 未应答 —— 门控仍工作，但不持久化。**台架上的 AT24C32 目前就是这个状态**（开机报 `EEPROM @0xA0  : FAILED at 0x0000`，设置写回 `(NOT PERSISTED - eeprom write failed)`）；而**同一条 PB10/PB11 上的 OLED 报 `Display : OK`**，说明总线、引脚与上拉都没问题，故障在 EEPROM 模块本身。详见 `docs/接线图-SG90.md` 的故障表 |
| `Position: timed estimate …` + `LIMITS=TIMED` | ✅ 正常 —— 默认配置就是不装限位，位置按行程时间推算 |
| `Position: limit switches …` | 说明烧的是 `-WithLimits` 变体，那两块板子必须真的接了 PA0/PA1 |
| 状态 LED 不亮 | 接在 **PC13** 了 —— 应该接 **PB4** |
| **发 `DOOR=OPEN` 门一动不动** | 系统未使能（先短按 KEY1）；或舵机没接 5 V／**舵机电源地与板地没接**（§2.1、§3.2）—— 后者是"舵机完全不动"最常见的原因 |
| 门报 `OPEN` 但实际没走到位（停在半路） | 位置是推算的：`DOOR_TRAVEL_MS` 比真门快 → 按实测把标定值**改大**（**宁长勿短**，见 `main.h`） |
| 舵机抖动、门一跳一跳地走 | 行程时间**太长**：每 20 ms 帧的位移掉到 SG90 死区（约 10–20 µs）以下 → 把 `TRAVEL=` 调到 **1000–1500 ms**（1500 ms → 13 µs/帧） |
| 舵机动了一下，板子就复位 | 舵机是从板上（3V3 或 ST-Link 的 5 V）取的电 —— 换成独立 5 V ≥ 1 A + 就近 470–1000 µF（§3.2） |
| 报 `FAULT: OPEN_TIMEOUT` / `CLOSE_TIMEOUT` | 说明状态机 2700 ms（默认行程 1500 + 1200 余量）内没收敛。默认构建里到位是按时间算的（1.5 s），本该收敛 —— 查故障闩锁与 `Motor_Run()` 是否被覆盖；**不要去改标定值** |
| 想知道"最多会驱动舵机多久" | `DOOR_TRAVEL_TIMEOUT_MS` = 当前 `DOOR_TRAVEL_MS`（默认 1500）+ `DOOR_TRAVEL_MARGIN_MS`（1200）= **2700 ms**：状态机不收敛时最多走这么久就停机锁故障。**它不知道门是否真的到位**，这是不限位时唯一的超程保护 |
| 舵机方向反 | 舵机**不能靠对调两根线反向**（信号只有一根）：改 `Core/main.h` 的 `SERVO_CLOSED_US` / `SERVO_OPEN_US`，或把舵盘/连杆装到反方向 |
