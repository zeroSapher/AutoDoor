# AutoDoor 舵机接线图（SG90 / TIM3_CH1，`sg90` 分支）

> **本文只讲本分支（`sg90`）的 SG90 舵机接线**：引脚、电源与地、每个模块怎么接、
> 上电前的万用表检查、故障对照，以及"这块板上没有什么"。
> **它取代 `docs/接线图.md` 里描述执行器的那几节** —— 那些节写的还是上一代的
> 130 直流电机 + L9110S/TB6612、PA4/PA5 方向脚、PB0 软件 PWM、`MOTOR_DEFAULT_DUTY`、
> SS34 续流二极管。`接线图.md` 中与执行器无关的部分（串口、OLED、EEPROM、
> 限位作废史）仍然有效。
>
> 本文的引脚、地址、时序全部来自**本分支的固件与 `generated/netlist.txt`**
> （`Core/main.h` 是机器可读的唯一真相，工具负责交叉校验）。
> **没有实测过的数字，本文不写。**

## 1. 系统框图

```
                        ┌──────────────┐
   USB-TTL (CH340) ─────┤ PA9 / PA10   │  115200 8N1（TX/RX 交叉）
   ST-Link (SWD)  ──────┤ PA13 / PA14  │  烧录 / 调试（必须保留）
                        │              │
   独立 5 V (≥ 1 A) ─┬──┤              │
        + 470~1000µF │  │              │
                     └─▶│ 红  ┌──────┐ │
        SG90 GND ◀──────┤ 棕/黑│ SG90 │PA6 ──▶ 橙/黄（50 Hz，1~2 ms 脉宽）
        （必须连板 GND） │     └──────┘ │
                        │  STM32F103   │
   OLED   SSD1306 0x78 ─┤ PB10 / PB11  │  ← 同一条软件 I2C（~50 kHz，需上拉）
   EEPROM AT24C32 0xA0 ─┤ PB10 / PB11  │  ← 与 OLED 共用 SCL/SDA
                        │              │
   KEY1..KEY4 → GND ────┤ PB5..PB8     │  ← 内部上拉，EXTI5..8
   门外 / 门内 → GND ───┤ PB12 / PB13  │  ← 内部上拉，EXTI12 / EXTI13
                        │              │
   有源蜂鸣器 ◀──────────┤ PB3          │  高电平响
   状态 LED ◀── 330 Ω ──┤ PB4          │  高电平亮
                        │              │
   3V3 ─────────────────┤ 3V3 → OLED / EEPROM / I2C 上拉
   GND（单点汇聚）──────┤ GND
                        └──────────────┘
```

## 2. MCU 引脚表

### 2.1 已使用的引脚

| 引脚 | 功能 | 方向 / 电气类型 | EXTI 与优先级 | 备注 |
|---|---|---|---|---|
| **PA6** | SG90 信号（`TIM3_CH1`） | 输出，复用推挽（`AF_PP`，50 MHz） | 不占 EXTI | 50 Hz 硬件 PWM，计数分辨率 1 µs；1000 µs = 关、2000 µs = 开 |
| **PA9** | USART1 TX → USB-TTL 的 `RXD` | 输出，复用推挽 | 不占 EXTI；`USART1_IRQn` 抢占优先级 1 | 115200 8N1，**永远不要分配别的功能** |
| **PA10** | USART1 RX ← USB-TTL 的 `TXD` | **浮空输入**（`IN_FLOATING`） | 同上 | TX/RX 必须交叉 |
| **PA13** | SWDIO（ST-Link） | 调试口复用 | — | 必须保留，不要当 GPIO 用 |
| **PA14** | SWCLK（ST-Link） | 调试口复用 | — | 必须保留 |
| **PB3** | 有源蜂鸣器 | 输出推挽，**高 = 响** | 不占 EXTI | 复位时是 JTAG 的 `JTDO`；固件 `App_JtagDisable()` 关掉 JTAG、保留 SWD 才空出来 |
| **PB4** | 状态 LED（串 **330 Ω** 到 GND） | 输出推挽，**高 = 亮** | 不占 EXTI | 复位时是 JTAG 的 `JNTRST`，同上 |
| **PB5** | KEY1（启停 / 使能门） | 输入，内部上拉（`IPU`），低有效 | **EXTI5**，`EXTI9_5` 向量，抢占优先级 3 | 上下沿都触发，软件消抖 20 ms |
| **PB6** | KEY2（切 AUTO / MANUAL） | 输入，内部上拉，低有效 | **EXTI6**，同上向量与优先级 | |
| **PB7** | KEY3（手动开门 / 日志上翻） | 输入，内部上拉，低有效 | **EXTI7**，同上向量与优先级 | |
| **PB8** | KEY4（手动关门；**长按 1.5 s = 急停**） | 输入，内部上拉，低有效 | **EXTI8**，同上向量与优先级 | |
| **PB10** | 软件 I2C **SCL**（OLED + EEPROM 共用） | 双向，开漏（`Out_OD`） | 不占 EXTI | **必须外接上拉**（4.7 kΩ 或 10 kΩ 到 3V3）；总线约 50 kHz |
| **PB11** | 软件 I2C **SDA**（OLED + EEPROM 共用） | 双向，开漏 | 不占 EXTI | 同上 |
| **PB12** | 门外（进门）存在检测 | 输入，内部上拉，低有效 | **EXTI12**，`EXTI15_10` 向量，抢占优先级 2 | 今天是一个按键 |
| **PB13** | 门内（出门）存在检测 | 输入，内部上拉，低有效 | **EXTI13**，同上向量与优先级 | 今天是一个按键 |
| **NRST** | 复位 | — | — | 板上已有 10 kΩ 上拉 + 100 nF |

> **优先级怎么读**：`NVIC_PriorityGroup_4` = 4 位抢占、**0 位子优先级**。所以子优先级
> 参数写了也不生效；同一向量只能有一个优先级，这就是 EXTI5..8 同为 3、EXTI12/13 同为 2 的
> 原因。次序是：限位（只有 `-WithLimits` 变体才有）0 > 串口 1 > 存在检测 2 > 按键 3。
>
> **存在检测只在下沿触发中断**（检测到人 = 拉低），松手/人离开由 1 ms 轮询记账；
> 按键是上下沿都触发。这一条在排查"门刚开就反向"时有用：**一个被一直拉低的输入，
> 电平兜底也会让门反转**，不一定需要新的边沿。

### 2.2 未使用 / 保留的引脚

| 引脚 | 状态 | 说明 |
|---|---|---|
| **PA0 / PA1** | **保留，不接任何东西** | 原名 `LIMIT_OPEN` / `LIMIT_CLOSE`：**限位开关已取消**（`AUTODOOR_NO_LIMITS = 1`），位置按行程时间推算。默认构建里这两脚不配时钟、不占 EXTI，接上去只会引入一个没人读的输入（`generated/mcu-pinout.csv` 标为 `unused`） |
| **PB0 / PB1 / PB2 / PB9 / PB14 / PB15** | 未使用 | **本分支不再有 `PWMA` / `STBY`** —— 那是直流电机分支的引脚。PB2 是 `BOOT1`（板上有下拉，会顶掉内部上拉）；PB9 会和四个按键抢 `EXTI9_5` 向量 |
| **PA4 / PA5 / PA7 / PA8 / PA15** | 未使用 | PA4/PA5 是直流电机分支的 `AIN1`/`AIN2` 方向脚，**本分支不再驱动它们**；PA15 是 JTAG 的 `JTDI`，关掉 JTAG 后空闲 |
| **PC13** | 保留，固件不驱动 | `main.h` 里指向它的 `LED_*` 是重写 `main.c` 时留下的**死宏**；状态 LED 在 **PB4**。接 PC13 会得到一个永远不亮的灯 |
| **PD0 / PD1** | 8 MHz 晶振（`OSC_IN` / `OSC_OUT`） | **本板晶振从来没起振过**，固件跑内部 8 MHz HSI（见 §3.2 末尾） |
| **PA9 / PA10** | 占用 | 115200 8N1 控制台，**不要改作他用** |
| **PA13 / PA14** | 占用 | SWD 烧录与调试，**必须留着** |

## 3. 各模块怎么接

### 3.1 电源轨与地（先看这一节）

| 电源 | 来源 | 供给谁 | 规则 |
|---|---|---|---|
| **3V3** | Blue Pill 板上的 AMS1117（输入来自 USB 或 ST-Link 的 5 V） | OLED、EEPROM、I2C 上拉、按键与存在检测（内部上拉） | 只有逻辑器件；**绝不带舵机** |
| **5 V（舵机专用）** | **独立 5 V 电源，≥ 1 A** | **只给 SG90** | 就近并 470–1000 µF；负极必须与板 GND 相连 |
| **5 V（板上）** | USB 或 ST-Link 的 5 V 脚 | 只给板子 | **不要用它带舵机** |
| **GND** | **单点汇聚** | 全部 | 舵机电源负极 → 一条粗线到舵机，**另一条**到板 GND，两条只在电源负极处汇合 |

**舵机电源的地必须接到板子的地。** 只接 5 V 与信号线、不接地时，PA6 的脉冲在舵机看来
没有参考电平 → **舵机一动不动**。这是"舵机完全没反应"最常见的原因，万用表通断档一量就知道。

**舵机必须有自己的 5 V（≥ 1 A）。** 不要用板的 3V3，也不要用 ST-Link 的 5 V 脚：
那种小 dongle 的 5 V 直通 USB，而**堵转的 SG90 会拉到几百毫安**，会把整块板子一起拉跌 ——
现象是"门动到一半板子复位"，看起来像固件 bug。**信号是 3.3 V 逻辑，舵机电源是 5 V，
两者只在"地"这一点上发生关系。**

### 3.2 SG90 舵机

| SG90 | 接到 | 说明 |
|---|---|---|
| 红 | **独立 5 V（≥ 1 A）** | 不要接板 3V3，也不要用 ST-Link 的 5 V |
| 棕 / 黑 | **该电源的负极**，并与**板 GND** 相连 | **必须共地** |
| 橙 / 黄 | **PA6** | 3.3 V 逻辑；不要接错到 PA4/PA5（那两脚在本分支是空的） |
| 470–1000 µF 电解 | 舵机 5 V ↔ 舵机 GND，**装在舵机那一端** | 正极对 5 V、负极对 GND |

- **舵机是位置执行器**：PA6 上是一串固定 50 Hz 的帧（周期 20 ms），脉宽就是角度 ——
  `SERVO_CLOSED_US` = **1000 µs**（关）、`SERVO_OPEN_US` = **2000 µs**（开）。
  SG90 的机械量程约 500..2500 µs，所以这 1000 µs 的差正好是 **90°** 的行程。
  舵机走到那个角度并**保持**：**没有占空比、没有滑行（coast）、没有方向对、没有换向死时间。**
- **速度来自行程时间**：`DOOR_TRAVEL_MS` 默认 **1500 ms**（走完 1000 µs 这一段），
  `TRAVEL=<ms>` 可在 **600..4000** 现场改、运行中即时生效。1500 ms →
  **13 µs/帧**（1000 µs ÷ 1500 ms × 20 ms），刚好越过 SG90 约 10–20 µs 的死区，
  所以门是**扫**过去而不是一格格跳；4000 ms 只剩约 5 µs/帧，是最容易抖的一端。
- `SPEED=50` 在本分支回 **`ERR N/A - SG90 speed is fixed (use TRAVEL=<ms>)`** ——
  舵机自己的速度不可设。本分支**没有** `MOTOR_DEFAULT_DUTY`、也没有 `MOTOR_DEADTIME_MS`
  在起作用（`main.h` 里留下的那两个直流电机宏被 `Motor_SetDuty()` 直接忽略）。
- **时钟**：`main.h` 里故意**没有** TIM3 的时钟常数。`Motor_Init()` 读**实际的 APB1
  定时器时钟**再算预分频，保证 1 µs 计数：本板 **8 MHz → `PSC=7`**（只有 72 MHz 才是 71）。
  本板那颗 8 MHz 晶振**从来没起振过**（用 SWD 强行打开 HSEON，`HSERDY` 始终不置位），
  MCU 跑**内部 8 MHz HSI**，50 Hz 帧与 1 ms 系统节拍仍然精确。
  **不要把 72 MHz 系统时钟写成事实**：写死它时帧会变成 5.5 Hz、脉宽 9 ms，舵机直接忽略信号
  不动，而 UART 与延时全都正常 —— 这个坑本分支真踩过。

### 3.3 共用 I2C 总线（OLED + EEPROM）

| 器件 | SCL | SDA | 地址 | 电源 |
|---|---|---|---|---|
| OLED SSD1306 0.96" | **PB10** | **PB11** | **0x78**（8 位；即 7 位 0x3C） | 3V3 |
| EEPROM AT24C32 | **PB10** | **PB11** | **0xA0**（8 位；即 7 位 0x50） | 3V3 |
| 上拉电阻 | PB10 → 3V3 | PB11 → 3V3 | 每个 4.7 kΩ（10 kΩ 也可以） | — |

- 软件 I2C，约 50 kHz。I2C 是**开漏**：**没有上拉就没有高电平**。开机横幅里的
  `I2C idle : yes` 就是"两条线释放后确实是高"的证据；`NO (bus held low)` 说明上拉缺失、
  SDA/SCL 接反、或器件短路。
- AT24C32：**4096 字节、32 字节一页**。布局是 **32 字节头 + 252 × 16 字节事件记录 +
  32 字节自检暂存页**（所以日志能存 252 条）。**A0/A1/A2 必须都接 GND**，否则 8 位地址
  不是 0xA0（7 位 0x50 + 三个地址位全 0）。
- **"总线是好的、但 EEPROM 不应答"这个组合，直接把故障指到 EEPROM 模块本身。**
  台架上就是这样：`Display : OK`（同一个 PB10/PB11）而
  `EEPROM @0xA0  : FAILED at 0x0000`。总线、引脚、上拉三者已经被 OLED 证明是好的，
  所以剩下的只有 EEPROM 模块自己的 **VCC / GND / SDA / SCL** 与 **A0/A1/A2 地址脚**。

### 3.4 四个按键（KEY1–KEY4）

| 按键 | 引脚 | EXTI | 短按 | 长按（按住 > 1.5 s） |
|---|---|---|---|---|
| KEY1 | PB5 | EXTI5 | 启停系统（`RUN`）—— **门指令的使能闸门** | 同短按 |
| KEY2 | PB6 | EXTI6 | 切 AUTO / MANUAL | 切 OLED 屏幕（状态屏 / 事件屏 / 日志屏） |
| KEY3 | PB7 | EXTI7 | 手动开门 | 退出日志屏，回状态屏 |
| KEY4 | PB8 | EXTI8 | 手动关门 | **急停**（长鸣 + `FAULT: ESTOP`，故障锁存，要 `RESET` 才清） |

- 接法：**一端接引脚，另一端接 GND**（不是接 3V3）。固件对这四个脚都开了**内部上拉**
  （`GPIO_Mode_IPU`），所以**不接外部上拉也能工作**；再加 10 kΩ 上拉 + 100 nF 到地
  只是提高抗噪性（可选，旁边有舵机在动时值得加）。
- `KEY_DEBOUNCE_MS = 20` ms、`KEY_LONGPRESS_MS = 1500` ms：点触短于 20 ms 被消抖忽略；
  按住超过门槛**只算长按，不会再补一个短按**。
- 一次按键只应产生**一条**事件。出现多条 = 消抖窗口不够，或 EXTI 引脚编号冲突
  （开机横幅会出现 `EXTI : N LINE CONFLICT(S) - an input has no interrupt!`）。

### 3.5 门内外存在检测（PB12 / PB13）

| 输入 | 引脚 | 今天的接法 | 换成真实传感器 |
|---|---|---|---|
| 门外（进门） | **PB12**（EXTI12） | 按键：一脚接引脚、一脚接 GND；按下 = 检测到人 | **E18-D80NK** 的 `OUT` → PB12 |
| 门内（出门） | **PB13**（EXTI13） | 同上 | **E18-D80NK** 的 `OUT` → PB13 |

- **低有效**：检测到人时把引脚拉低，空闲时靠上拉为高。两脚共用 `EXTI15_10` 向量、
  抢占优先级 2（比按键高：有人来了必须立刻知道）。
- **E18-D80NK 是 NPN 集电极开路输出**，也就是"低有效、对着上拉"—— 与今天的按键**同一种
  电气形状**，所以它是**直接替换**：`OUT` 接引脚、传感器自己接 **5 V** 与 **GND**，
  而它的 GND **必须与板 GND 相连**。状态机、日志、上报都不用改。
- **上拉**：固件已经开了内部上拉，所以模块没有上拉也能工作；若模块自带（或你外加）
  上拉，**先确认它上拉到 3V3 一侧**再接到引脚上。
- 传感器的检测距离与阈值调节是模块自己的事，**本文不给数字**（没有实测过）。

### 3.6 蜂鸣器（有源，PB3）

| 接法 | 说明 |
|---|---|
| **模块自带驱动** | 信号脚 → **PB3**；VCC/GND 接 3V3/GND（3.3 V 型模块）或 5 V（看模块） |
| **裸蜂鸣器** | PB3 → **1 kΩ** → NPN 基极（S8050）；蜂鸣器接集电极与 +5 V；并 **1N4148** 续流（阴极对 +5 V） |

**高电平响**（`BUZZER_ACTIVE_HIGH = 1`）。固件用节奏区分开机就绪、开门、关门、到位、
故障、急停等事件。

### 3.7 状态 LED（PB4）

**PB4 → 330 Ω → LED 阳极 → LED 阴极 → GND**（高电平亮）。串限流电阻是**必需**的。

| 门态 | 闪烁模式 |
|---|---|
| INIT | 快双闪 |
| IDLE | 常灭 |
| OPENING | 常亮 |
| OPEN | 慢闪（倒计时中） |
| CLOSING / REVERSING | 快闪 |
| STOPPED | 双闪（故障或急停） |

> **不要接 PC13。** `main.h` 里指向 PC13 的 `LED_*` 宏固件从不驱动（见 §2.2）。

### 3.8 USB-TTL（控制台）

| USB-TTL | 接到 | 说明 |
|---|---|---|
| `TXD` | **PA10**（MCU 的 RX） | 必须交叉 |
| `RXD` | **PA9**（MCU 的 TX） | 必须交叉 |
| `GND` | **GND** | 不接 GND 就完全没有输出 |
| `VCC` | **不接** | 板子另有一路供电时，两个电源并联会互相灌 |

115200 8N1。**TX/RX 没交叉是"串口完全没输出"的第一大原因。**

### 3.9 ST-Link（SWD）

| ST-Link | 接到 |
|---|---|
| `SWDIO` | **PA13** |
| `SWCLK` | **PA14** |
| `GND` | **GND** |
| `3V3` | 3V3（只在用 ST-Link 给板子供电时） |

> ST-Link 上电后**不要**同时打开 STM32CubeProgrammer / Keil —— 它们会独占探针，
> 现象是"找不到调试器"。固件只关 JTAG、**保留 SWD**，所以烧录后再连也连得上。

## 5. 上电前检查（万用表，10 分钟）

| # | 检查 | 判定 |
|---|---|---|
| 1 | 舵机 5 V 电源**空载**输出 | 4.9–5.1 V |
| 2 | Blue Pill 3V3 对 GND | 3.2–3.4 V |
| 3 | **舵机电源 GND ↔ 板 GND（通断档）** | **必须导通** —— 不通就是"舵机不动"（§3.1） |
| 4 | 舵机三线（**先不通电**）：红 ↔ 舵机 5 V、棕/黑 ↔ 舵机 GND、橙/黄 ↔ PA6 | 各自导通；且**信号线对 5 V、对 GND 都不导通** |
| 5 | 470–1000 µF 电解极性 | 正极对舵机 5 V、负极对 GND |
| 6 | 板 5V / 3V3 **不要**与舵机 5 V 相连 | 不导通（两路 5 V 各自独立） |
| 7 | I2C `PB10` / `PB11` 对 3V3 | 约 3.3 V（上拉在、总线空闲） |
| 8 | **PA0 / PA1 悬空** | 不接任何东西（限位已取消，§2.2） |
| 9 | **PA9 / PA10** | 只接 USB-TTL，且 TX/RX 交叉 |
| 10 | 上电顺序 | **先上板子**（看开机横幅与 `I2C idle : yes`），**最后**才上舵机电源 |
| 11 | 上电瞬间 | 蜂鸣器一声（就绪）、LED 快双闪、串口出开机横幅 |

## 6. 故障对照表

| 现象 | 先查什么 |
|---|---|
| **舵机完全不动** | ① **舵机电源的地没接到板地**（最常见，§3.1）；② 舵机 5 V 没接或电源没开；③ 信号线不在 PA6 上（本分支 PA4/PA5 是空的）；④ 系统未使能 —— `DOOR=OPEN` 会回 `ERR BUSY (state=IDLE run=0)`，先短按 KEY1 |
| **舵机抖动 / 门一跳一跳地走** | 行程时间**太长**：每 20 ms 帧的位移掉到 SG90 死区（约 10–20 µs）以下。把 `TRAVEL=` 调到 **1000–1500 ms**（1500 ms → 13 µs/帧）；4000 ms 只剩约 5 µs/帧 |
| **舵机动一下，板子就复位** | 舵机是从**板上**取的电（3V3 或 ST-Link 的 5 V）。换成独立 5 V ≥ 1 A + 就近 470–1000 µF，并与板共地（§3.1、§3.2） |
| **舵机嗡嗡响、发热但门不动** | 目标角度顶在机械止挡上：连杆顶死，或 `SERVO_OPEN_US` 相对本机构太大。SG90 顶住止挡时是嗡嗡叫，不是继续转 |
| **OLED 全黑 / 不显示** | `I2C idle : yes` 但 `Display : not found` → OLED 的 VCC/GND、地址 0x78、PB10/PB11；`I2C idle : NO (bus held low)` → **上拉没接**、SDA/SCL 接反、或器件短路 |
| **`EEPROM @0xA0  : FAILED at 0x0000`**、**`Log : UNAVAILABLE - running with defaults`** | **这就是台架现状**（不是接线接错在别处）：AT24C32 不应答，于是所有设置写都回 `(NOT PERSISTED - eeprom write failed)`，**日志与持久化设置都无法工作**。**同一条 PB10/PB11 上的 OLED 报 `Display : OK`**，证明总线、引脚与上拉都是好的 → 故障在 **EEPROM 模块本身**：查它的 VCC/GND/SDA/SCL，以及 **A0/A1/A2 是否都接了 GND**（否则地址不是 0xA0）。**它一应答，不需要改任何固件**：`boot#` 递增、`TRAVEL=`/`DELAY=`/`MODE=` 的重新装载都会自动回来 |
| **串口完全没有输出** | `PA9`/`PA10` **没交叉**（TX→RX、RX→TX）；波特率不是 115200；USB-TTL 的 GND 没接；**或 PA9 被占用了**（它是控制台 TX，不能分给别的东西） |
| **串口有乱码** | 波特率不对；或时钟不对 —— 本固件直接用内部 **8 MHz HSI**，不用外部晶振、也不启用 PLL |
| **某个按键没反应** | 按键是不是一端接引脚、**另一端接 GND**（接 3V3 就永远无效）；引脚对不对（KEY1–4 = **PB5–PB8**）；开机横幅有没有 `EXTI : N LINE CONFLICT(S)`；以及**一次按键是否只产生一条事件**（多条 = 消抖不够或 EXTI 号冲突） |
| **门刚开就立刻反向 / 关不上** | 存在检测输入被**一直拉低**（按键卡住、E18-D80NK 一直判"有人"、或该脚被短到 GND）：状态机会 `REVERSE`，或回 `ERR OCCUPIED (person detected in doorway)`。先在串口看有没有人在事件 —— **电平**就能触发兜底反转，不需要新的边沿 |
| **状态 LED 不亮** | 接在 **PC13** 了 —— 应该接 **PB4**，并串 **330 Ω** |
| **门报 `OPEN` 但实际没走到位（停在半路）** | 位置是**推算**的：`DOOR_TRAVEL_MS` 比真门快，固件在门还没到时就认为到位并停下。按实测把标定值**改大**（宁长勿短） |

## 7. 这块板上**没有**什么

| 没有 | 说明 |
|---|---|
| **H 桥 / 电机驱动模块** | 没有 L9110S、没有 TB6612，也没有 `AIN1/AIN2/PWMA/STBY` 这些脚 |
| **直流电机** | 执行器是 SG90 舵机：舵机内部自带驱动电路，MCU 只给它一串脉冲 |
| **续流二极管（SS34）** | **不需要**：没有 H 桥去承受感性反峰，舵机的负载由它自己处理 |
| **限位开关** | 默认构建（`AUTODOOR_NO_LIMITS = 1`）不装：PA0/PA1 悬空，位置按行程时间推算。只有 `-WithLimits` 变体才读它们 |
| **可调占空比 / 换向死区** | 没有 `MOTOR_DEFAULT_DUTY`、没有 `MOTOR_DEADTIME_MS` 在起作用；`SPEED=` 会被拒 |
| **`VM` / `AO1` / `AO2` 这些节点** | 那是直流电机分支的接线名，本分支不再存在 |
